# Budgets (Presupuestos) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Monthly per-category budgets with a Profile screen, a Home row and one budget notice merged into the post-save feedback.

**Architecture:** A new stamped `presupuesto` table with its own repository and one SQL aggregate for
the month's spent; pure rules in `core.model` decide state, per-day amount, pace day, suggestion and
the single notice; a `feature.budgets` MVVM screen, a Home row and an optional budget line on
`ManagementFeedback` consume them.

**Tech Stack:** Kotlin 2.4.10, Compose Multiplatform 1.11.1, SQLDelight 2.3.2, Koin 4.2.2, kotlinx-datetime.

**Spec:** `docs/superpowers/specs/2026-11-18-budgets-design.md` — read it first; this plan does not
repeat its rules.

Paths below: `cm` = `shared/src/commonMain/kotlin/com/kurobello/tallybook`, `sq` =
`shared/src/commonMain/sqldelight/com/kurobello/tallybook/core/database`, `ct` =

## Global Constraints

- Code, identifiers, tests, comments in English; domain vocabulary stays Spanish (`Presupuesto`, `monto`, `categoria`, `moneda`, `fecha`, `GASTO`).
- Never `Dispatchers.*` directly; inject `CoroutineDispatcher` (`named(DispatcherQualifier.IO)`).
- Read "today" only through `CivilToday` in ViewModels; repositories take `today: LocalDate`.
- Exact `Long` minor units; amounts ≤ `Money.MAX_MINOR_UNITS`; never add currencies together.
- Every write: one `changeClock.next()` per transaction, strict inserts, reads exclude tombstones.
- One-shot events: `Channel(Channel.BUFFERED).receiveAsFlow()`; screen state: `StateFlow<UiState>` + `Actions` interface.
- Copy per `docs/wording.md`: `values` (es, tú), `values-es-rAR` (voseo), `values-en`, `values-pt-rBR` (idiomatic, not literal). No "alerta", no exclamation marks, no warning icons.
- `es` copy fixed by the spec: "Vas bien en %1$d de %2$d", "$ X por encima de tu presupuesto", "Te quedan $ X", "A este ritmo llegarías al tope el día %d", "Te quedan $ X · $ Y por día", Home "N presupuestos para revisar", notice "%1$s: ya estás por encima de tu presupuesto este mes" / "%1$s: te quedan %2$s este mes" / "%1$s: a este ritmo llegarías al tope el día %2$d", action "Ver", suggestion "Tu promedio: %s".
- Every Kotlin task ends green on `./gradlew detekt ktfmtCheck` (apply with `./gradlew ktfmtFormat`).
- Commits: conventional (`feat:`, `fix:`, `test:`, `docs:`), each ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- Huge amounts near `MAX_MINOR_UNITS`: the pace comparison must not overflow `Long`; it reports PACE or not, never crashes. → Task 1 test `paceNeverOverflowsNearTheCap`.
- Last day of the month and short months: per-day uses days left including today (1 on the last day); the pace day stays inside the month. → Task 1 tests `perDayOnLastDayIsRemaining`, `paceDayFallsInsideFebruary`.
- A gasto in another currency in a budgeted category must not touch the budget. → Task 2 test `spentIgnoresOtherCurrencies`, Task 1 test `noticeIgnoresOtherCurrency`.
- A save touching a parent and a child budget with the same state shows the child's notice. → Task 1 test `noticeTieGoesToSubcategory`.
- Deleting a custom category leaves no orphan live budget; hiding one keeps it. → Task 2 tests `deletingCustomCategoryTombstonesItsBudgets`, `hiddenCategoryKeepsCounting`.

SQL (in `Presupuesto.sq`; `12.sqm` holds the `CREATE TABLE` and index):
```sql
CREATE TABLE presupuesto (
    id TEXT NOT NULL PRIMARY KEY,
    categoria_id TEXT NOT NULL,
    moneda TEXT NOT NULL,
    monto_minor INTEGER NOT NULL CHECK (monto_minor > 0),
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    deleted_at TEXT
);
CREATE INDEX presupuesto_categoria ON presupuesto(categoria_id);

selectLiveWithSpent:
SELECT p.*, categoria.nombre AS categoria_nombre, categoria.padre_id AS categoria_padre_id,
  COALESCE((SELECT SUM(m.monto_minor) FROM movimiento m JOIN cuenta c ON c.id = m.cuenta_id
    WHERE m.deleted_at IS NULL AND m.tipo = 'GASTO' AND c.moneda = p.moneda
      AND m.fecha BETWEEN :start_date AND :end_date
      AND (+m.categoria_id = p.categoria_id
           OR +m.categoria_id IN (SELECT id FROM categoria WHERE padre_id = p.categoria_id))), 0) AS spent_minor
FROM presupuesto p JOIN categoria ON categoria.id = p.categoria_id
WHERE p.deleted_at IS NULL;
```
