# Learning from Sentence Corrections Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record every hand-made correction between Continue and Save, and turn a correction the user repeats into a personal rule (1st time offered, 2nd consistent time applied) for tipo, categoría, medio, cuenta and frecuencia.

**Architecture:** A new stamped table `correccion_frase` (migration `11.sqm`) with a repository. A pure `CorrectionRules` computes rules in memory from the last 180 days of records. `MovimientoEntryEngine.interpret` takes the rules, applies or offers them, and exposes per-field `leido` (before rules) and `propuesto` (after rules). The ViewModel snapshots the interpretation at Continue, tracks which fields the user set by hand, and after a successful save writes one record per hand-set field.

**Tech Stack:** Kotlin 2.4.10, SQLDelight (verifyMigrations), Koin, kotlin.test (commonTest), Robolectric host tests.

**Spec:** `docs/tasks/phrase-corrections.md` (the authority; read it first).

## Global Constraints

- No `Dispatchers.Main/IO` in shared code; the repository gets the IO dispatcher by Koin qualifier like its siblings.
- Every Gradle command through the chrisbanes `gradle_run.py` wrapper (`create`/`run`/`finish`).
- Before reporting a task done: `./gradlew ktfmtFormat detekt` clean, no new suppressions unless repo precedent.
- Commit per task (conventional commits, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`), never push.
- Physical Xiaomi only for device checks.
- Rule numbers: window 180 days; ≥ 2 agreeing records; latest record must agree; 1 agreeing record = offered; words shorter than 3 characters never form rules.

## Rulings (controller, from code mapping)

- No erase-all-local-data path exists yet; this feature adds none. The future erase/Drive work must include `correccion_frase` (note it in `docs/tasks/google-drive-persistence.md`).
- Records are written after the save succeeds, in their own transaction: a failed save records nothing; a crash between the two writes loses only that save's records.
- Medio and cuenta share one `SelectionOwner`, so separate `medioEdited` / `cuentaEdited` flags are added (set by `onMedioSelected` / `onCuentaSelected` only); a medio adapted by a cuenta or tipo change is not hand-set.

## Review Focus

1. A field filled by a default (default cuenta/medio, Otros) must never produce a record (Task 4 `defaultsAreNotCorrections`).
2. A learned rule must never override an explicit sentence word unless its records corrected that same reading (Task 3 `anExplicitMedioWinsOverAHabit`).
3. A failed save must record nothing (Task 4 `aFailedSaveRecordsNothing`).
4. Parts record their own words and values; Join records one structure record (Task 4 parts tests).
5. Rules refresh live after a save, so the very next sentence sees the new offer (Task 4 integration test).

### Task 2: Pure rule engine

**Files:**
- Create: `shared/src/commonMain/kotlin/com/kurobello/tallybook/core/data/entry/CorrectionRules.kt`
- Test: `shared/src/commonTest/.../core/data/entry/CorrectionRulesTest.kt`

**Interfaces:**
- Consumes: Task 1 model.
- Produces:

```kotlin
internal sealed interface RuleOutcome {
  data object None : RuleOutcome
  /** One agreeing record, or rules that disagree across the sentence's words. */
  data class Offered(val values: Set<String>) : RuleOutcome
  data class Applied(val value: String) : RuleOutcome
}
internal class CorrectionRules private constructor(/* word+campo → records */) {
  /** [leido] is the parser's own reading; a rule overrides it only if its records corrected that reading. */
  fun outcome(words: List<String>, campo: CampoCorreccion, leido: String?): RuleOutcome
  companion object {
    val EMPTY: CorrectionRules
    fun from(records: List<CorreccionFrase>, now: Instant): CorrectionRules
  }
}
internal val LEARNED_CAMPOS = setOf(TIPO, CATEGORIA, MEDIO, CUENTA, FRECUENCIA)
internal val RULE_WINDOW = 180.days
```
- Per word and campo (records within the window, word length ≥ 3, campo in `LEARNED_CAMPOS`): let `latest` be the newest record. Applied when ≥ 2 records have `guardado == latest.guardado`; Offered(setOf(latest.guardado)) when exactly 1 agrees; None when `latest.guardado` is null. Across the sentence's words: all Applied with one value → Applied; Applied with different values → Offered(all their values); otherwise the union of Offered values, or None.
- `leido` gate: when the caller's `leido != null` and the outcome is Applied, keep it Applied only if at least 2 of the agreeing records have `leido` equal to the caller's `leido` (the user corrected that same reading twice); otherwise downgrade to None (the explicit word wins).

```kotlin
/** Per learned campo: the parser's own reading (`leido`) and what the app proposed (`propuesto`). */
internal data class FieldReadings(val leido: Map<CampoCorreccion, String?>, val propuesto: Map<CampoCorreccion, String?>)
internal data class OfferedValues(val categoriaIds: List<String>, val medios: Set<MedioPago>, val cuentaIds: List<String>)
```
- Value encodings (spec): tipo / medio / frecuencia = enum `name`; categoría = id; cuenta = id; monto = `"<minorUnits> <MONEDA>"`; fecha = ISO date.
- Order (spec): tipo rule first (fills only when `parsed.tipo == null`, replacing `impliedTipo`; overrides a verb only through the `leido` gate), then ranking with the final tipo; categoría: exact-subject history (`learnedCategoriaId`) > Applied word rule > dictionary preselection; Offered categoría ids are added in front of the ranking's dimmed suggestions (deduplicated, `MAX_SUGGESTION_CHIPS` respected). Cuenta: Applied fills an undecided `SentenceCuenta` (ignore archived/deleted ids: only ids present in `catalogs.cuentas.cuentas`); Offered adds to `alternativeIds`. Medio: Applied fills an undecided `SentenceMedio` (then `forTipo`), Offered adds to `candidates`; a named cuenta's implied medio still wins. Frecuencia: Applied fills `parsed.frecuencia == null`. Words = `suggestionTokens(query.subject)`; parts use their own subject with the shared tipo.
